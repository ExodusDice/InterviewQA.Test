Finkub QA Testing API Report 1.0.0

This report documents the automation testing execution and coverage performed on the Mock Employee REST API database. The test suite was run natively inside a Docker container, executing Gherkin statements powered by Python's Behave BDD Cucumber framework.

Employee Controller endpoints verified by the Cucumber automation suite

post /api/v1/employees Create a new employee record (Positive & Negative validation)
Request Body Schema (application/json)
{
  "firstName": "string (Required)",
  "lastName": "string (Required)",
  "email": "string (Required, Must be valid format)"
}
Automated Test Executions (Cucumber Results)
Scenario: Create Employee successfully (Positive) passed

Steps:

  • Given the employee API is available at "http://localhost:8887"
  • When the user sends a POST request with payload: 
    {
  "firstName": "John",
  "lastName": "Doe",
  "email": "john.doe@test.com"
}
  • Then the API response status code should be 201 (Created)
  • And the database is checked (GET `/api/v1/employees`) and confirms the email 'john.doe@test.com' has been saved and assigned a new unique ID.
Scenario: Create Employee with invalid email (Negative) passed

Steps:

  • Given the employee API is available at "http://localhost:8887"
  • When the user sends a POST request with an invalid email payload: 
    {
  "firstName": "Jane",
  "lastName": "Doe",
  "email": "invalidemail"
}
  • Then the API response status code should be 400 (Bad Request)
  • And the response JSON body's default message contains: "must be a well-formed email address"
get /api/v1/employees/{id} Fetch an employee record by their ID (Positive & Negative validation)
Parameters
Name Description
id * required
integer (path)		 The unique integer ID of the employee record to retrieve.
Automated Test Executions (Cucumber Results)
Scenario: Get Employee by ID (Positive) passed

Steps:

  • Given the employee API is available at "http://localhost:8887"
  • And a valid employee exists and has ID 1
  • When the user sends a GET request to "/api/v1/employees/1"
  • Then the API response status code should be 200 (OK)
  • And the response body contains the correct employee details: 
    {
  "id": 1,
  "firstName": "John",
  "lastName": "Doe",
  "email": "john.doe@test.com"
}
Scenario: Get Employee by non-existing ID (Negative) passed

Steps:

  • Given the employee API is available at "http://localhost:8887"
  • When the user sends a GET request to "/api/v1/employees/9999"
  • Then the API response status code should be 404 (Not Found)
  • And the plain-text error response body exactly matches: "Employee not found with ID 9999"
